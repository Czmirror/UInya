# Completion report

## 概要

3〜5行で、何が変わるか（使う人から見て）・なぜ変えたか・人が確認・判断すること（なければ「なし」）だけを書きます。
書き方は[Writing for humans](../rules/core/writing.md)に従います。検証の詳細は下に書きます。

## 詳細

該当しない項目は書きません。ただし、検証・実動検証・人間の確認は、適用外や未実施でも理由を書きます。

- 関連Issue:
- 実装内容:
- 主な変更ファイル:
- 仕様書（作成・更新したパス、または作らなかった理由）:
- 試験仕様書（パスと各ケースの実施結果。成功 / 失敗 / 未実施 / 適用外）:
- 設計上の判断:
- 仮の調整値（名前・値。今回変えたものは変更前の値も）:
- 計画の確認項目・受け入れ条件の結果と証拠への参照（適用外 / 未実施 / 未確定 / 問題ありを区別）:
- 実行したvalidation（コマンド・対象revision・結果）:
- test結果（成功 / 失敗 / skipped / blocked）:
- 実行できなかったvalidation・理由:
- 画面の設計図と実際の画面の比較（設計図を作った場合。番号ごとに設計どおり / 違う（理由）、スクリーンショットの有無）:
- 対象stackが要求する実動検証（[Runtime verification](../rules/core/runtime-verification.md)。対象外なら理由）: 環境・revision/差分・scene・手順/期待結果・実施者/手段・結果・error・warning出力・証拠・未検証範囲と解除に必要な対応:
- AIのfinal diff review（対象・判断根拠・修正、自己レビュー / 独立レビューの別）:
- コメント/責務レビューの結果と未解決事項（Runner結果と分け、分割延期があれば理由・承認の出典）:
- 人間の確認・承認（対象・出典・確認できた範囲。未確認は未確認）:
- 運用上の未検証範囲（新規sessionのルール読込・承認前停止など。自動検証と区別）:
- 範囲外で見つけたこと（実装していない問題。Issueの下書き、または既知の問題の置き場所への追記先。なければ「なし」）:
- 残存リスク:
- migrationの有無・適用の有無:
- dependency変更の有無・理由:
- public API変更の有無:
- 人間による確認が必要な事項:
- 状態（HumanReview待ち / Blocked（実動確認待ちを含む） / 人間受け入れ済み）:

未実行や失敗を成功に変換しません。適用外の検証も理由を明記します。
