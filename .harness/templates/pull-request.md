# Pull request body

導入先のPR本文の見本です。projectにPRテンプレートがあれば、その見出しを優先し、先頭に「概要」を足します。
書き方は[Writing for humans](../rules/core/writing.md)に従います。

```markdown
## 概要

<!-- 3〜5行。何が変わるか（使う人から見て）、なぜ変えたか、人が確認・判断すること（なければ「なし」）。 -->

## 人が確認すること

<!-- 実動確認待ちなら、5手順以内の確認手順（起動する場面・操作・期待する結果・見る表示やログ）。なければ「なし」。 -->

## 範囲外で見つけたこと

<!-- 実装していない問題と、Issueの下書きまたは既知の問題の置き場所。なければ「なし」。 -->

<details>
<summary>検証と詳細</summary>

<!-- 計画・承認の出典、実行した検証と結果、実行できなかった検証と理由、変更ファイル、残るリスク。 -->

</details>
```

実動検証が残るPRはdraftのままにし、タイトルの先頭に「[実動確認待ち]」を付けます（[Runtime verification](../rules/core/runtime-verification.md)）。
