# Release: <version>

- version（前回 → 今回）と根拠:
- version方式（既存の方式、または提案して人間が決めた方式と出典）:
- 対象branch・revision:
- 前回のリリース（tag・revision）:
- 前回からの変更（CHANGELOG・リリースノートのパス、または要約）:
- 破壊的変更・導入先や利用者への注意（判定できない変更は未確定と書く）:
- migration・dependency変更の有無:
- 検証（コマンド・対象revision・結果。失敗・未実施は理由）:
- rollback手順と、戻せない変更:
- 実行する操作（tag作成・push、公開、Release作成、deployなど）:
- 承認（操作ごとの対象・出典・日時。公開したversionとtagは取り消せないことを伝えたか）:
- 実行結果（tag・artifact・公開先・日時。途中で止まった場合は完了した操作）:
- リリース後の確認（内容・結果。AIが確認できない範囲は未確認と書く）:
- 未確認事項・残るリスク:

承認欄をAIが記入しても承認の証明にはなりません。人間の会話・レビュー等の出典を示します。
小さなリリースは関連する項目だけで構いません。手順は[Release](../rules/core/release.md)に従います。
