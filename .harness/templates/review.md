# Final diff review

共通の項目はこのファイルにあります。差分が次の条件に当たる場合は、対応する観点ファイルも読みます。
条件に当たるか判断がつかない場合は読みます（[Rule discovery](../rules/index.md)の読み込みの原則）。

| 差分の内容 | 観点ファイル |
| --- | --- |
| 入力・認可・外部送信・秘密情報・依存に触れる | [Security](review/security.md) |
| DB・migration・状態・データ形式、または計画の図（状態遷移・処理の流れ・テーブル）に触れる | [Data](review/data.md) |
| testを追加・変更した、または挙動を変えた | [Tests](review/tests.md) |
| コード・公開API・設定・ログ・文書を変えた | [Docs and comments](review/docs-comments.md) |

独立reviewerに任せる場合は[Independent review](independent-review.md)を使います。

- レビュー対象のcommit / 差分・検証結果:
- 計画の確認項目ごとの結果・証拠（対象file / symbol / 差分・確認内容・不足、適用外 / 未実施 / 未確定は理由）:
- 既存ユーザー変更を保護しているか:
- バグ、境界値、失敗経路、認可・データ境界:
- 最終差分が仕様書の受け入れ条件を満たすか、仕様の変更が仕様書に反映されているか:
- 設計書の記載不足を逆提案したか、未承認の業務条件を勝手に実装していないか:
- 採用した責務・依存境界を守っているか、不要な層や抽象化を増やしていないか:
- 追加・変更したファイルの責務（SRP。行数では判断しない）: 新しいファイルは1つの責務として説明でき、変わる理由が1つか。既存の複数責務のファイルは、計画で承認された分割、または分けない理由に沿っているか:
- 冒頭の役割を書き足したファイル: 書き足した担当が既存と同じ理由で変わるか。別の理由なら計画で分ける案と比較したか、分けない理由が承認されているか:
- 責務・コメントの意味レビュー（[Workflow](../rules/core/workflow.md)）。モデルの分離だけでentry point/UIも確認済みにしていないか。変更file/symbolと根拠、未確認・未解決・承認された分割延期の区別:
- 共通化は同じ知識に基づくか、推測だけの機能・抽象化や範囲外のついで修正がないか:
- 新しい関数・型・定数・handler・表示文言に同じ知識の既存実装が残っていないか。置き換えた旧実装、参照されなくなったfile・export、同じ定義の二重の正本、本番と別のtest用実装が残っていないか（[Coding principles](../rules/core/principles.md)）:
- 処理再利用に合成・委譲を検討したか、継承の理由と置換可能性、委譲先の責任が明確か:
- Harness / CI / 品質基準の弱体化がないか:
- 読んだ観点ファイルと、条件に当たらず読まなかった観点:
- 指摘（重要度・場所・根拠・修正案）:
- 修正と再検証:
- 残存リスク・人間レビュー事項:

AIの自己レビューを独立レビューや人間の承認として扱いません。
全項目の形式的なチェックは不要です。関連する計画項目を参照し、実際に照合した証拠を残します。
Runner成功やREADMEの記載だけで、コメントの契約説明や事前の仕様承認を確認済みにしません。
