# User content

利用者が入力した内容（投稿、コメント、レビュー、ユーザー名、プロフィール、チャット、ゲームのランキングの名前など）を
他の利用者に表示する機能を追加・変更する場合、NGワード（表示させたくない語）や予約語の判定を作る・直す場合に適用します。

目的は、悪口・個人情報・なりすましの名前などがそのまま公開される事故と、正しい投稿まで止めてしまう誤判定の両方を防ぐことです。
何を止めるかはサービスごとに違うので、このルールは基準やNGワードの中身を決めず、作るときに守ることだけを書きます。

既存ルールとの分担:

- 長さ・型・形式の検証、制御文字や見えない文字（zero width等）の扱いは[Input validation](input-validation.md)。
- 表示するときのescape（XSS対策）は[Security](security.md)と[Web](../stacks/web.md)。NGワードの判定はXSS対策の代わりにならない。
- 止めた投稿の確認・解除の画面、リストを更新する画面は[Admin screens](admin-screens.md)にも従う。
- 止めた記録に投稿の本文を残す場合は、[Logging](logging.md)と[Sensitive data](sensitive-data.md)に従って個人情報として扱う。
- 投稿の内容をメールに載せる場合は、同じ判定を通したうえで[Email](email.md)に従う。

## 何を止めるかは人が決める

- 何を止めるか（悪口・差別的な語、電話番号や住所などの個人情報、宣伝のURL、なりすましの名前など）と、
  どこに表示されるか（誰でも見られる・本人だけ・管理者だけ）を、作る前に仕様書に書く。子ども向けかどうかで基準が大きく変わるため。
- 基準とNGワードの中身はサービスの方針なので、AIが決めない。AIは止める対象の種類と、それぞれの扱いの候補を示し、人間が選ぶ。
- AIはNGワードの一覧そのものを作らない。testには、意味のない仮の語（例: `NGTEST`）か、人間が決めた語を使う。

## NGワードの置き場所

- NGワードをコードに直接書かない。DBか、公開しない設定に置き、運用担当が更新できるようにする。語を足すたびに開発者とdeployが要ると、対応が遅れるため。
- repositoryには、testに使う少数の語と、例外リストの形（項目と書き方）だけを置く。公開repositoryにリストを置くと、回避のしかたまで読まれるため。
- 判定はserverで行う。リストをブラウザ・アプリに送らない。送ると一覧が見え、判定を飛ばした投稿もできてしまうため。
  ブラウザ側の判定は、入力中の案内として使うだけにする。
- リストの変更（誰が・いつ・何を）を記録し、変更できる人を権限で絞る。
- ユーザー名用の予約語（運営、公式、admin、support、system等）は、NGワードとは別のリストとして持つ。なりすましを防ぐため。

## 判定のしかた

- 判定の前に表記をそろえる。全角と半角（Unicodeの正規化NFKC）、大文字と小文字、ひらがなとカタカナ。
  さらに、間に挟んだ空白・記号・見えない文字を除いた形でも判定する（例:「ば か」「ば.か」）。
- そろえた文字は判定にだけ使う。保存・表示には、利用者が入力した文字をそのまま使う。
- 日本語は単語の区切りがないので、部分一致で判定すると正しい語も止まる（例:「バカ」で「バカンス」が止まる）。
  例外リスト（止めない語）を持ち、誤判定しやすい語をtestに入れる。
- 多数の語を1本の正規表現につないだり、利用者の入力から正規表現を作ったりしない。
  長い入力で処理が極端に遅くなる（ReDoS）ことがあるため。文字列の検索か、多数の語を一度に探す仕組み（Aho-Corasick等）を使う。
- 投稿内のリンクは`http`・`https`だけを許可する（`javascript:`等を通さない）。外部リンクには`rel="ugc nofollow"`を付ける。
  宣伝の投稿が多いサービスでは、リンクを許可するドメインの許可リストも検討する。
- AIが作った文章（チャットの返答など）を利用者に表示する場合も、同じ判定を通すかを計画で決める。

## 止めたあとの扱い

- 止めたときの扱いを、表示する場所ごとに決める。弾く（投稿させない）、伏せ字にする（例:「＊＊」）、人の確認待ちにする、のどれか。
  ユーザー名やランキングの名前のように、一度表示されると後から直しにくい場所では、弾くことを提案する。
- 利用者には「使えない語が含まれています」のように理由の種類だけを伝える。どの語で止まったかを細かく示すと、言い換えで回避されやすいため。
- 止めた記録（いつ・どの規則で・どう扱ったか）を残す。投稿の本文を含める場合は、見られる人と保存期間を決める。
- 誤判定を人が直せるようにする。止めた投稿を管理画面で確認して公開・却下でき、必要なら例外リストに語を足せるようにする。
- NGワードだけでは防げない投稿（言い換え、画像）のために、通報と非表示の手段を設けるかを計画で決める。
  削除の依頼に応じる手順や、法令上の義務に当たるかはAIが断定せず、判断に必要な事実を整理して人間が決める。

## 検証

- testには、NGワードそのもの、表記ゆれ（全角・半角・カタカナ・空白や記号を挟んだもの）、誤判定しやすい正しい語、
  例外リストの語、予約語のユーザー名、長い入力を入れる。
- 止めたときの表示（弾く・伏せ字・確認待ち）を、実際の画面で確かめる。
- リストを更新したとき、再起動やdeployなしで反映されることを確かめる。

## このルールで扱わないこと

- NGワードの一覧そのもの、業種ごとの基準。
- 画像・動画・音声の内容の判定。外部の判定サービスを使う場合は、送る内容を[Sensitive data](sensitive-data.md)に従って決める。
- 外部の判定サービス・libraryの使い方。

## 記録する場所

NGワードの置き場所、止めたあとの扱い、誤判定を直す担当は、ステアリング`.harness/steering/tech.md`の「投稿の確認」に要点だけを書きます。
ステアリングがない導入先では`AGENTS.md`に書きます。NGワードの中身はステアリングに書きません。
