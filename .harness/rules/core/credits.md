# Copyright, credits, and licenses

projectのライセンス・著作権表示を追加・変更する場合、クレジットやライセンス文の表示を作る・更新する場合、
配布物・公開物を作る場合に適用します。
出典と利用条件の記録は[Assets](assets.md)と[Libraries and dependencies](libraries.md)を正本とし、このファイルは記録をもとに何をどこへ表示するかを決めます。
ライセンスの両立や義務の解釈について、AIは確認した事実と不明点を示すだけで、法的な最終判断は人間（必要なら専門家）に委ねます。

## projectのライセンスと著作権表示

- ライセンスの選択・変更は人間が決める。AIは候補と影響（再配布・改変・特許の扱い、依存や素材のライセンスとの両立）を示し、`LICENSE`を独断で追加・変更しない。
- 著作権者名と年を、gitのauthor・アカウント名・過去のファイルから推測して書かない。人間に確認する。
- ソースファイルごとの著作権表示・SPDX識別子は、projectに方針がある場合だけ付ける。冒頭の役割説明（[Comments](comments.md)）とは別物として扱い、どちらかで他方を代用しない。
- `LICENSE`がないrepositoryは、他者に利用を許諾していない状態になる。公開・配布を計画する場合は、この状態と決めるべきことを人間に示す。

## 表示が必要なものの洗い出し

配布物・公開物を作る前に、表示が必要なものを一覧にします。

- [Assets](assets.md)と[Libraries and dependencies](libraries.md)の記録で、クレジット表記またはライセンス文の同梱が必要なもの。
- 配布物に含まれる依存: bundleしたJavaScript、静的にリンクしたbinary、同梱したruntime・エンジン本体など、package managerで入れたものも対象にする。開発・test・buildだけで使い配布物に含まれない依存は対象外。
- 表示の種類を区別する: 作者名などのクレジット表記、ライセンス文・著作権表示の同梱（MIT・BSD・Apache Licenseの`NOTICE`・SIL Open Font Licenseなど）、利用規約が求める表記（ロゴ・splash・指定の文言）。
- 依存のライセンス一覧を出すツールが言語やエンジンにあれば使い、手で書き写さない。ツールの出力も記録と照合する。
- 確認できない項目は「未確認」とし、完了報告で人間の確認事項に挙げる。

## 表示する場所

どこに表示するかはprojectが決めます。決まっていなければ、AIは必要な表示と候補の場所を示して人間に確認します。

- repository: `LICENSE`、第三者の表示をまとめたファイル（例: `THIRD_PARTY_NOTICES`、`CREDITS`）。
- 配布物: ライセンス文・著作権表示のファイルが成果物（zip・installer・Web export等）に実際に含まれていることを、成果物を開いて確認する。repositoryにあるだけで含まれたと判断しない。
- アプリ内: ゲームのクレジット画面、Webのabout・フッター、設定画面のライセンス一覧など。
- 配布先: ストア・ゲーム投稿サイト・packageの公開ページの説明欄。

クレジット画面など実行時に表示するものを実装・変更した場合は、表示されることを確認します。
[Runtime verification](runtime-verification.md)の対象では、その必須検証に従います。

## AIで生成したもの

- 生成ツールの利用規約が求める表記は、[Assets](assets.md)の記録どおりに表示へ反映する。
- 配布先（ストア・投稿サイト等）がAI利用の開示を求めるかどうかと、開示の内容は人間が判断する。AIは生成した素材・コードの一覧と、使ったツールを示す。

## 更新のタイミング

- 表示が必要な素材・依存を追加・削除したPRで、表示も同時に更新する。リリースのときに履歴から思い出して書くより漏れが少ないためです。
- リリースの準備では、表示が現在の素材・依存と一致し、成果物に含まれているかを確認する（[Release](release.md)）。
